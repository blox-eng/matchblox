# The Demo Host Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A person with no host taps **Try a demo**, is paired with a host called `demo` that runs on the phone, uses the real console on it, and reaches an invite to set up matchblox.

**Architecture:** The Go console and the real service run in the app's process, joined by `net.Pipe`, over a temp copy of the fixture machine, with the replay's scripted world as the service's runner. A C library exposes it to Swift, and the app treats it as one more source of terminal bytes behind `ConsoleConnection`. The demo host is an ordinary `Host` with a fixed fingerprint.

**Tech Stack:** Go 1.26 with cgo (`-buildmode=c-archive`, XCFramework), Bubble Tea v2, Swift, SwiftUI, SwiftTerm, XcodeGen, GitHub Actions on macOS 15 with Xcode 26.

**Spec:** `docs/superpowers/specs/2026-11-02-on-device-demo-design.md`. Issue #282. The throwaway proof is branch `spike/on-device-demo`: read its `cmd/mbdemolib/main.go`, `ios/spike/probe.c` and `.github/workflows/spike-demo.yml`.

## Global Constraints

- Work in `~/dev/matchblox-demo`, on a new branch `feat/282-demo-host` from `design/282-on-device-demo`. Never touch `~/dev/matchblox`.
- Use absolute paths in shell commands. A relative path is read against `~/dev/matchblox` and refused.
- tmux only on a throwaway `tmux -L` server, with `HOME` and `XDG_RUNTIME_DIR` in a temp folder. Never the default server.
- Signed Conventional Commits, never `--no-verify`, no WIP, never force-push.
- Before each commit: `rg -i -f <(sed '/^$/d' ~/.config/builder/denylist.txt) <(git diff --cached)`. Only Go import lines of the module path may match.
- No other product's name in code, docs or commits. Dev tracking on GitHub only.
- Merging, pushing an `ios-v*` tag and restarting live consoles each need the owner's yes.
- Install line, verbatim: `curl -fsSL https://matchblox.sh | sh`.
- Refusal line, verbatim: `This is a demo. Install matchblox to do that.`
- Invite heading, verbatim: `Your agents wait the same way.`
- The host's name, everywhere: `demo`. No network, camera, keychain, push or Island use on the demo host.
- Swift cannot build on Linux. iOS tasks are verified by pushing the branch and reading CI. Go tasks run here.

## Review Focus

Each line has its test in the task named.

1. The app is killed, or sent to the background, mid-demo and opened again: it starts fresh and leaves no temp tree behind (Task 1, `TestStopLeavesNothing`, `TestAStartAfterAStopIsFresh`).
2. The phone turns on its side at a question, under 16 rows: the console says it is too short and nothing is stuck; turning back shows the menu (Task 3, `TestTheDemoSurvivesATurn`).
3. The demo host is removed from the list: the notice must not tell the person to remove a key on a host that does not exist (Task 7, `testRemovingTheDemoSaysNoKey`).
4. A real pairing link arrives during the demo: the demo stops, the real host opens, and `demo` is gone (Task 7, `testPairingARealHostRemovesTheDemo`).
5. The temp folder cannot be written, as on a full phone: the app says what happened and offers **Try again**, never a blank terminal (Task 1, `TestStartNamesWhatFailed`; Task 8 shows it).
