# The chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The console shows the selected agent's live tmux screen beside Sessions and sends keys to it. The answer peek goes away. The iOS app gets a seven-key bar.

**Architecture:** The console sends `watch:<pane>`. The service captures that one pane every 150 ms and pushes a new `screen` message to that console only, when the text changes. Keys go back as `keys:<pane>` acts, one in flight at a time, with PID and seen-frame guards. The TUI draws the screen in the right half (Wide/Medium) or full-screen (Narrow). The iOS app replaces SwiftTerm's accessory with seven 44 pt keys.

**Tech Stack:** Go, Bubble Tea v2 (`charm.land/bubbletea/v2`), lipgloss v2, `github.com/charmbracelet/x/ansi`, tmux; Swift, SwiftTerm, UIKit.

**Spec:** `docs/superpowers/specs/2026-10-29-ask-mode-design.md` (read it first; this plan argues from it).

## Review Focus

1. The selection changes while a key is in flight. The queued keys must go to the pane they were pressed at, or be dropped with a flash. They must never go to the new selection. → Task 4 test `TestQueuedKeysStayWithTheirPane`.
2. Two consoles watch two different panes. Each gets only its own screen. → Task 1 test `TestTwoConsolesWatchTheirOwnPane`.
3. A session restarts in the same pane (new PID) while the chat is open. The next key is refused, and the flash says so. → Task 2 test `TestKeysRefusedForANewAgentInThePane`.
4. A pane wider than the view, full of `─` rules, on a 44-column phone. Rules are cut, prose wraps, and the prompt stays on screen. → Task 3 test `TestFitKeepsTheBottomAndCutsRules`.
5. A console with no connection (`m.lost`) presses a key in the chat. Nothing queues forever. The flash says `not sent, no connection`. → Task 4 test `TestKeysWithNoConnection`.
