# The key belt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The iPhone app's key bar becomes the key belt of the design: a row of keys you arrange, which turns round the phone's sides, clicks under the thumb, and opens into a matchbox tray of layouts. Its command keys run each agent's commands through the console.

**Architecture:** One command table (`testdata/keys/commands.json`) is read by the Go console and by the app. The console takes `ESC _ matchblox;cmd=<id> ESC \` as tmux user keys 901+, and runs each command behind the chat's guards. It sends `ESC _ matchblox;agent=<id> ESC \` to the app through tmux passthrough. In the app, MatchbloxKit holds the belt's pure maths (cells, fold, detents, coast, ticks, tap versus drag), the layouts, and Mine. A hand-built UIKit `BeltView` with a matchbox tray replaces `KeyBarView`. The island's match drawing moves into one file that the app and the island both compile.

**Tech Stack:** Go (Bubble Tea v2, tmux); Swift 5.10, UIKit, SwiftUI (only for the shared match), SwiftTerm 1.20.0, xcodegen, XCTest.

**Spec:** `docs/superpowers/specs/2026-10-30-key-belt-design.md`. Read it whole before any task. Mockup (the reference for every look and motion): <https://claude.ai/artifact/VezKp1djbb3mpk6Lm1NNBF>, version `1793359559-edd5`. Where the text and the mockup disagree, the mockup wins on looks and the spec text wins on behaviour.

## Review Focus

1. A drag that starts on a key and ends on the same key, within 8 pt, is a tap; one that moves 8 pt and comes back is not a press. Test `testDragThatReturnsIsNotATap` (Task 4).
2. A fast flick that crosses many detents in one frame gives one tick per detent, not one per frame; the home stop's firmer click fires once. Test `testFlickTicksOncePerDetent` (Task 4).
3. A command key pressed while the chat's agent is unknown (`agent=` empty) sends nothing and flashes `commands run from the chat`. Test `TestCommandWithNoChatSendsNothing` (Task 2).
4. Mine is edited down to `◂` alone, or holds keys wider than the screen: the belt still has a home stop and never rests between keys. Test `testMineOfOneKeyStillHasHome` (Task 5).
5. The app gets a partial `ESC _ matchblox;agent=` across two reads, or `agent=` inside other output: the filter joins it, draws none of it, and passes every other byte through. Test `testAgentSignalSplitAcrossReads` (Task 5).

  - `public struct BeltFold: Equatable { public let x: CGFloat; public let angle: CGFloat /* degrees, + left edge, − right */; public let anchorLeft: Bool; public let shade: CGFloat; public let visible: Bool }`, and `public static func fold(x0: CGFloat, width: CGFloat, screen: CGFloat) -> BeltFold`.   - `public struct BeltMotion: Sendable { public init(keys: [BeltKey], geometry: BeltGeometry); public var offset: CGFloat; public mutating func drag(by: CGFloat) -> [BeltTick]; public mutating func step(dt: TimeInterval) -> [BeltTick]; public mutating func release(velocity: CGFloat); public func settleTarget() -> CGFloat; public func x(ofKeyAt: Int) -> CGFloat; public var atRest: Bool; public var homeOffset: CGFloat }`. The ring wraps the keys endlessly; detents sit at each key's left side + gap; `homeOffset` puts key 0 (`◂`) at the left edge. Coast velocity decays ×0.93 per 16 ms; settle eases to the nearest detent.
  - `public enum BeltTick: Equatable { case detent, home }`: one per detent crossed, `home` when that detent is key 0.
  - `public struct TapOrDrag { public static let threshold: CGFloat = 8; public init(); public mutating func moved(by: CGFloat); public var isDrag: Bool }` (once a drag, always a drag).
