# The Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The console's home becomes a board: every match in the column of what it needs, with a peek, filters for chain and host, a bottom strip, a context menu and copy, on a phone and on a desk.

**Architecture:** The board is new code in new files of `internal/app/`, written as pure functions of `Model` that return lines and tap spans. It reads the same `proto.State` the Sessions tab reads today. One last task wires it in as the home and removes what it replaces, one commit for each removal. Nothing in `internal/service`, `internal/proto` or the CLI changes in this plan, except one read of tmux's `set-clipboard`, one more row in the service's key-guard test, and whatever Task 0 step 1 finds that the app's belt needs (the owner decides that there).

**Tech Stack:** Go, Bubble Tea v2 (`charm.land/bubbletea/v2`), lipgloss v2, bubbles `key`. Golden frames through `check` in `internal/app/screens_test.go`.

**Spec:** `docs/superpowers/specs/2026-11-10-the-board-design.md`. Sketch: `design/0019-the-board.html` (open it in a browser; it runs).

**This plan is the first of three.** It covers "The order of the work", step 1 (the board). Step 2 (Machine and its views) and step 3 (the daily record, the work grid and the charts that need it) each get their own plan when this one is approved. Until step 2 lands, the `machine` tab shows today's Machine panel.

## Global Constraints

- Code starts after #326 lands on `main`, or after matchblox-chain agrees the file boundaries in writing (Task 0). The merge order is #355 → #361 → #326 → #367, and mbbox runs it.
- Work in the worktree `/home/blox-master/dev/matchblox-372`. Never change the branch of another session's checkout.
- Every commit is a signed Conventional Commit. Never `--no-verify`. No WIP commit.
- Before each commit: `git diff --cached | rg -i -f ~/.config/builder/denylist.txt` prints nothing.
- Each removal is its own commit.
- No change to `matchblox sessions --json`, `peek`, `send` or any other command's output.
- Every colour is a token of `app.Tokens(dark)`. A colour that is not a token fails the replay test.
- Every explanation and every string the person reads is ASD-STE100: one idea a sentence, active, present tense. Copy follows DESIGN.md §7.
- Motion comes from the clock (`m.now()`, a function on `Model`), never from a frame count (DESIGN.md §4 rule 4). `--no-motion` shows end states.
- A tap is never consent. A destructive act runs only on a typed `y` in the consent box.
- The four columns, their names and their rule are the spec's "Columns" table, word for word.
- Layout limits are the code's own: `layout(cols, rows)` in `internal/app/layout.go` (`Narrow`, `Medium`, `Wide`). The live view beside the board starts at 152 columns.
- The digits' dead time after a new peek is 400 ms. The long-press is 480 ms. The landing glow is 1.2 s.
- `go test ./...` passes before each commit that touches Go.

## Review Focus

1. **A press that the terminal does not report.** tmux or Pocket may send no mouse release, no motion and no right button. Then the long-press, the drag and the right-click never fire. Expected: every act they give has a key (`c`, the menu on a key, see Task 9), and nothing breaks. Test in Task 9.
2. **A state that changes between the peek and the digit.** The match asks a new question while the owner reads the old one. Expected: the digit is refused with the service's own words. Test in Task 7.
3. **More cards than rows.** 25 matches on a 34-row phone, 12 in one column. Expected: the chosen card is whole, and `↓ N more` says what is under. Test in Task 4.
4. **Names and questions that are too long, wide or empty.** A 60-character session name, a question in CJK, a match with no last message. Expected: every row is exactly as wide as the screen, cut with `…`, and an empty message draws no quote. Test in Task 3.
5. **Every filter on at once.** `NEEDS YOU` hidden, a chain filter, a host filter and a search, while a match on another host asks. Expected: the header counts it, and one tap reaches it. Test in Task 6.
