# Plan: a builder jumps to any of their first nine sessions with one key

## What the code holds today

- `sample.Session` (`internal/sample/sampler.go:31`) has no number. A session ends by leaving `Snapshot.Sessions`. `SessionID` changes on a cleared chat and can be empty (Codex, Cursor). `chains.Member{SessionID, Pane, PID, Start}.Same` (`internal/chains/chains.go:34`) is the identity rule that survives both.
- The service rebuilds `s.cur` on each `publish` (`internal/service/service.go:648`). The stores that persist are separate files next to state.json. `internal/holds` is the model: `Open` loads the file and moves a corrupt one aside, and each change saves through a temp file and a rename. `Prune` takes the sessions present. A missed sample makes every session look gone: `sampleMissedLocked()` (`internal/service/chains.go:503`).
- The list row is `sideRow` (`internal/app/siderow.go:39`): `mark` (`▌` or a space), the chain link, the match, the name.
- `⌥s`/`⌥n` (`internal/panes/flip.go`) bind `-n M-s`/`M-n` with `if-shell -F '#{@matchblox_match}'`. In a marked pane, `handOff` takes the client to the console (`goHome`), then sends the console an APC `<kind>=<tty> <pane>`. In any other pane, the key goes on as typed. `keycmd.ParseAPC` accepts `flip`, `next` and `open` (`internal/keycmd/flip.go:41`). The console's `flipAPC` (`internal/app/flip.go`) handles it. `walkFrom` sets `m.askedBy = tty`, then `m.goInto(m.opt.Host, pane)`, which runs `switch-client -t <pane>` for that tty.
- No tmux binding can tell a phone client: the app connects as `xterm-256color`. Only the console knows it: `m.pocketClient(tty)` (`internal/app/boardkeys.go:724`). The line already types the letter for a phone's joined Esc (`sidekeys.go:148`).
- `TestKeymapsHaveNoCollisions` (`internal/app/keys_test.go:100`) leaves out the `room` keymap, which holds `alt+s` and `alt+n`. `TestTheDocsNameEveryKeyAndOnlyRealOnes` (`internal/app/docs_test.go:67`) wants each key-table cell in `docs/keys.md` to equal a binding's key or help key.

## Lens findings

- Engineering, one owner: the service owns the numbers. The console, the phone's console and the pane binding all read `Session.Number`. No second count anywhere (Task 2).
- Engineering, identity: a cleared chat changes `SessionID`, so the store uses `chains.Member.Same` (Task 1).
- Engineering, a missed sample: without the guard, one bad tmux read would free every number and shuffle them (Task 2, `TestAMissedSampleKeepsTheNumbers`).
- Architecture, a new store file: `numbers.json` beside `holds.json`, in the same open, save and move-aside pattern. An old console reads `number` as absent: `omitempty`, and an old peer shows no column. No proto version bump.
- Architecture, an agent's tools: no tmux binding knows a phone client. The pane key hands the console the digit and the client. The console types the key back for a phone (Task 5, hostile test). The hand-off skips `goHome`, so a phone's client never leaves its pane.
- Design: the number column is dim, and the key line names `⌥1-9 jump` once. An empty number keeps the column's width, so names do not shift as sessions come and go (Task 3).
- Design, an error: `no session 7: the list numbers 1 to 5` names what exists (Tasks 4 and 5).
- Engineering, a guard the suite lacked: `room` was not in the collision layers. Adding it is the fix the touched code needs (Task 4).

## Changes during build

- 2026-11-25, Task 1: `chains.Member.Same` compares only session ids when both members have one, so it cannot find a cleared chat (a new SessionID in the same pane, PID and start). The store also matches pane, PID and start, as the service's `refreshMembersLocked` does. `Assign` returns an error too, so a failed save is logged and not lost.
- 2026-11-25, Task 2: `cmd/matchblox/push_test.go` had a helper named `numbers`, which clashes with the new import in `main.go`. It is now `pushNumbers`, the `push.Numbers` it builds. A missed sample publishes no numbers (0s) for that one doc; the store keeps them, so the next good sample shows them again.
