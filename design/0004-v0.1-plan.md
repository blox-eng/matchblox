# matchblox v0.1 Implementation Plan (milestones 3 to 9)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship matchblox v0.1 as the front door of `0003-v0.1-front-door.md`: the mark and a recorded replay, the queue and all panes, the console as a control pane from a phone, night mode, the look, setup as doors with one-command install, and the site and repository files.

**Architecture:** Milestones 1 and 2 of plan 0002 are merged (dd68e1d, 353e1f3, f6d2269): a service on the host and a console client over `proto` messages. This plan adds units to the service (`hooks`, `queue`, `panes`, `night`, `setup`) and to the console (start screen, queue, overnight view, doors). The replay is a Go test that runs the real service and console in one process on fixtures.

**Tech Stack:** Go 1.26, Bubble Tea v2, Lip Gloss v2, huh v2, BurntSushi/toml, GitHub Actions, go-semantic-release, Cloudflare Workers static assets, MkDocs Material + mike.

**Spec:** `design/0003-v0.1-front-door.md`, which changes `design/0001-v0.1.md`. Language: ASD-STE100. Code names stay as they are. This plan replaces milestones 3 to 8 of `design/0002-v0.1-plan.md`. Where a task says "as 0002 Task N", read that task in 0002 and apply the changes listed here.

## Global Constraints

- All Global Constraints of plan 0002 apply, except the paths and budget lines for the stoker (`keys/<provider>.key`, `stoker.jsonl`), which are removed.
- New state files: `$XDG_STATE_HOME/matchblox/night.json` (mode) and `night.jsonl` (log).
- Install command: `curl -fsSL https://matchblox.sh | sh`. Until the first release exists, every copy button and every doc gives `go install github.com/blox-eng/matchblox/cmd/matchblox@latest`.
- Demo host `ws-1`. No real machine, person or company in code, tests, fixtures, commits or docs.
- The site CSP stays `script-src 'self'`: no inline script or style, no third-party resource.
- The start screen is < 600 ms, any key stops it, and `--no-motion` or `NO_MOTION=1` shows its last frame only.
- Night mode runs no model, answers no prompt, sends no "continue", and runs no destructive step except the guarded compact.
- One pull request for each milestone, squash merge, 7 required checks green, CodeQL threads resolved.

## Review Focus

1. **The fixture host name leaks.** On fixtures the console must show the name from `<fixtures>/proc/sys/kernel/hostname`, never `os.Hostname()`. Owner: Task 3.1 (`TestFixtureHostName`).
2. **Night mode types into a session that just became busy.** The idle-pane guard is checked on the service right before each send. Owner: Task 6.1 (`TestNightSkipsBusySession`).
3. **Night mode loops on one session** (a compact that does not lower the context). At most one compact for each session for each 30 min, at most 30 steps for each night. Owner: Task 6.1 (`TestNightRateLimits`).
4. **A door writes a file the builder already changed.** Each door reads the file again just before it writes, keeps a backup, and refuses when the file changed after the preview. Owner: Task 8.1 (`TestDoorRefusesChangedFile`).
5. **The replay test is flaky in CI** (async samples). It waits on what the screen shows, with a 10 s bound for each step, and never on sleeps. Owner: Task 3.3 (`TestReplayWaitsOnScreen`).
