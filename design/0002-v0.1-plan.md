# matchblox v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship matchblox v0.1 as specified in the design: a host service and a console client, the "waiting for you" queue, all panes, remote mode over SSH stdio, the stoker, the look, one-command install, and the two sites.

**Architecture:** Port `builder-tui` into `blox-eng/matchblox`. Then split it at the seams that already exist (`ui.Options.Source`, `Git`, `Run`, `Check`, `OnSnapshot`, `History`): the service owns those functions, and the console receives `proto` messages through a `transport.Conn`. New units (`hooks`, `panes`, `stoker`, `setup`) plug into the service. The console draws only what it receives.

**Tech Stack:** Go 1.26, Bubble Tea v2, Lip Gloss v2, Bubbles v2, Harmonica, ntcharts v2, huh v2, BurntSushi/toml, gopsutil v4 (non-Linux only), GitHub Actions, go-semantic-release, Cloudflare Workers static assets, MkDocs Material + mike, VHS.

**Spec:** `design/0001-v0.1.md`. Language: ASD-STE100. Code names stay as they are.

## Global Constraints

- Module path: `github.com/blox-eng/matchblox`. Binary: `matchblox`. Entry: `cmd/matchblox/main.go`.
- `CGO_ENABLED=0`. Targets: linux and darwin on amd64 and arm64. Windows builds compile; sessions need WSL.
- The console does not read the machine. The service does not import `internal/app`. A test enforces both (Task 2.1).
- No unit builds a shell string from data. Steps are `[]string` argv.
- Paths:
  - config `~/.config/matchblox/config.toml`
  - keys `~/.config/matchblox/keys/<provider>.key` (0600)
  - state `$XDG_STATE_HOME/matchblox/` (default `~/.local/state/matchblox/`)
  - socket `$XDG_RUNTIME_DIR/matchblox/matchblox.sock`, else `<os.TempDir()>/matchblox-<uid>/matchblox.sock`, directory mode 0700.
- Protocol: newline-delimited JSON, `proto.Version = 1`, `hello` first from each side.
- Safety: read-only by default; `Enter` runs only non-destructive steps; destructive steps need `x` then typed `y`; guards are checked again on the service host just before each step; steps run with a 2 min timeout, `GIT_TERMINAL_PROMPT=0`, `GIT_SSH_COMMAND=ssh -o BatchMode=yes`, at the lowest CPU priority.
- Budget: service idle < 1% of one core and < 40 MB RSS; console idle < 0.5%; `matchblox hook` < 50 ms; queue update < 1 s; first frame < 300 ms.
- Cadence: counters 2 s, processes 10 s, containers and GPUs 60 s, git 5 min; renderer ≤ 15 fps and only on change.
- Colours, motions, breakpoints and copy rules: design §10, exactly.
- Public repository: no real machine names, people, companies or incidents in code, tests, commits or docs. Demo host is `ws-1`.
- Licenses: copy no code from AGPL, proprietary or restricted-license projects (design §15).
- All changes go to `main` through a pull request with squash merge. One pull request for each milestone.

## Review Focus

1. **The service is not running, or is an older version.** The console must start the service, or show the exact command that updates the host. It must not hang or show an empty screen. Owner: Task 2.4 (`TestConsoleStartsService`, `TestVersionMismatchShowsFix`).
2. **The SSH connection drops in remote mode.** The console shows "connection lost", tries again with backoff, and keeps the last state as stale (Heal motion on recovery). Owner: Task 4.1 (`TestReconnectAfterDrop`).
3. **Two consoles connect at the same time and both confirm the same destructive step.** The service runs it once. The second gets "already done" from the guard. Owner: Task 2.3 (`TestDoubleConfirmRunsOnce`).
4. **A hook event arrives when the service is down or the socket is stale.** `matchblox hook` writes to the spool and returns within 50 ms. It never blocks the agent. Owner: Task 3.1 (`TestHookWithoutServiceSpools`, `TestHookStaleSocket`).
5. **The model sends back a step that is not in the proposal set or not on the allowlist.** The stoker rejects it, logs it, and runs nothing. Owner: Task 5.2 (`TestAutoRejectsUnknownStep`).
