# Landing brief — wedge, user-first

Date: 2026-11-24. Spec: `design/0021-wedge-against-ade.md`.  
Apply these words and visuals in **`www/` in the same feat PR**.

## Voice (Jobs / Apple, deslopified)

- Start from the person: too many agents, one mind, keep the fire going.
- Say what they can **do** and how it **feels**. Never lead with stack,
  RAM, “ADE”, “GPU terminal”, or competitor names.
- One idea per section. Cut adjectives that sell (“powerful”, “next-gen”,
  “100x”). Prefer short, certain sentences.
- Show the product (replay). Let the picture carry complexity.
- Lightness = quiet UI, one safe answer, stays out of the way — not a
  MiB badge on the hero.

## Keep

- Brand hero: **Light an idea. Keep it burning.**
- Install in the first viewport (already there).
- Desk / phone / stoker / pocket as separate sections with one job each.
- Existing replays as the visual plane.

## Change (copy)

### Hero sub (replace today’s tech-tinged line)

**Today:**  
`One terminal console for every coding agent you run. See what needs you on one board, and answer from the card.`

**Proposed:**  
`When an agent needs you, you see it. You answer. You move on.`

Optional second line only if the layout still breathes (not required):  
`Every agent you run, one place that stays calm.`

### Section “Every agent, one box” lede

**Today:** leans on pane / `ctrl+q` / terminal mechanics early.

**Proposed:**  
`All your agents in one list. The one that needs you is on top. Open it, and you are already in the work.`

(Keys can stay in the replay caption or a short note under the stage — not the lede.)

### Chain / stoker / pocket

Keep intent; trim any sentence that starts with a tool name. Lead with the
outcome (team hears each other; night work waits for your word; buzz when
something needs you).

### What we deliberately do **not** put on the landing

- Go, MiB, RSS, Electron, “native TUI”, “GPU”, ADE, competitor tables.
- Feature grids, plugin marketplace energy, “Ship 100x”.
- A resource strip that brags about memory (that lives on Machine in the
  product, and as a README footnote for builders).

## Visual ask

- No new hero chrome. No cards in the hero. No floating badges.
- If a replay is refreshed later: Machine may quietly show a `matchblox`
  line with size — as product truth inside the demo, not as a marketing
  callout over the hero image.
- Prefer removing clutter over adding “lightness” stickers.

## README (this repo — for contrast)

Builders get one category line and a measured footprint footnote. That is
for people who install from GitHub. The **marketing** page stays human.
